# Dynamic Entities

The module creates TypeORM entities dynamically at runtime:

- `ConfigSection` entity
- `ConfigData` entity
- `ConfigMigration` entity (migration tracking)

These entities are exported via tokens so you can plug them into `TypeOrmModule.forRootAsync`.

## Exported entity tokens

- `TOKEN_CONSTANT.CONFIG_SECTION_ENTITY`
- `TOKEN_CONSTANT.CONFIG_DATA_ENTITY`
- `TOKEN_CONSTANT.CONFIG_MIGRATION_ENTITY`

## Entity customization

You can customize table names, column lengths, and the common temporal column type via `entityOptions`:

```typescript copy
CrudConfigModule.register({
 entityOptions: {
  timestampColumnType: "timestamptz",
 },
});
```

`timestampColumnType` is passed to all nine temporal columns in `ConfigSection`, `ConfigData`, and `ConfigMigration`, including their TypeORM create/update date decorators. It defaults to `Date` ([`CONFIG_ENTITY_CONSTANT.DEFAULT_TIMESTAMP_COLUMN_TYPE`](/docs/nestjs-crud-config/api-reference/constants/config-entity-constant)), which TypeORM maps to the timestamp type of each driver: `timestamp` on PostgreSQL and `datetime` on MySQL, MariaDB, SQLite (`better-sqlite3`) and SQL.js, so the default entities work on every one of them. Set a driver-specific type, such as `"timestamptz"` for PostgreSQL, only when the application needs it. Changing it for an existing database still requires the corresponding schema migration.

In async registration, provide entity customization, including `timestampColumnType`, via `staticOptions.entityOptions` (and `staticOptions.migrationEntityOptions` for migration tracking table settings) so controllers and providers use the same entities.

## Default schema

### Configuration Sections table (`config_section`)

```sql copy
CREATE TABLE config_section (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  name VARCHAR(128) NOT NULL UNIQUE,
  description VARCHAR(512),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### Configuration Data table (`config_data`)

```sql copy
CREATE TABLE config_data (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  name VARCHAR(128) NOT NULL,
  value VARCHAR(8192) NOT NULL,
  environment VARCHAR(64) NOT NULL,
  description VARCHAR(512),
  is_encrypted BOOLEAN DEFAULT FALSE,
  section_id UUID NOT NULL REFERENCES config_section(id) ON DELETE CASCADE,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(name, environment, section_id)
);
```

The migration `status` column is a TypeORM `simple-enum`: a native enum on PostgreSQL, MySQL and MariaDB, and a `varchar` with a `CHECK` constraint on SQLite and SQL.js.

## Constraint and index names

Every constraint and index has an explicit name, built from the table name. With the default table names they are:

| Table | Name | Kind |
| --- | --- | --- |
| `config_section` | `PK_config_section` | primary key |
| `config_data` | `PK_config_data` | primary key |
| `config_data` | `FK_config_data_section` | foreign key to `config_section` |
| `config_data` | `UQ_config_data_name_environment_section` | unique (`name`, `environment`, section) |
| `config_migrations` | `PK_config_migrations` | primary key |
| `config_migrations` | `UQ_config_migrations_name` | unique (`name`) |
| `config_migrations` | `IDX_config_migrations_status` | index (`status`) |
| `config_migrations` | `IDX_config_migrations_started_at` | index (`startedAt`) |
| `config_migrations` | `IDX_config_migrations_created_at` | index (`createdAt`) |

A custom table name replaces the table part: `tableName: "app_data"` gives `PK_app_data`, `FK_app_data_section` and `UQ_app_data_name_environment_section`. PostgreSQL cuts names longer than 63 bytes, so keep custom table names short enough.

## Migration Notes

- **5.1:** the constraints and indexes have the explicit names above instead of TypeORM hash names (`PK_5d278b2c9701f26df2db108b10a`) and `idx_config_migration_*`. Rename them in an existing schema with a migration (`ALTER TABLE … RENAME CONSTRAINT`, `ALTER INDEX … RENAME TO`), or write the new names into a fresh baseline. `createDynamicEntityClass` takes `uniques` as `{ columns, name }` entries instead of column lists.
- **5.0:** `createdAt` and `updatedAt` are TypeORM create and update date columns, so `updatedAt` changes on every save and update; in CrudConfig 4 it kept the insert time. On MySQL and MariaDB `updatedAt` gains `ON UPDATE CURRENT_TIMESTAMP`; other schemas do not change.
- **5.0:** `timestampColumnType` defaults to `Date` instead of `"timestamp"`, and the migration `status` column is a `simple-enum` instead of an `enum`. PostgreSQL schemas do not change. MySQL and MariaDB schemas created with the old default need their temporal columns converted to `datetime` before the upgrade. See [Migrating to 5.0](/docs/nestjs-crud-config/guides/migrating-to-5-0#database-schema).
