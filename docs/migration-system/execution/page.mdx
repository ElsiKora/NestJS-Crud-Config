# Execution

Migrations are executed via:

- `ConfigMigrationService`
- `ConfigMigrationRunnerService`

They store execution status in the migration tracking entity.

## Running on startup

When `migrationOptions.isEnabled` and `migrationOptions.shouldRunOnStartup` are true, migrations run automatically on application bootstrap.

## Transaction ownership

`useTransaction` defaults to `true`. Transaction-enabled execution owns one Automator transaction named `crud-config-migrations`; migration history writes and each callback share its exact `EntityManager`. Rollback execution always uses the same named owner.

Pass the callback manager as `eventManager` to every `CrudConfigService` operation. Automator 3 treats `runWithEntityManager` as join-only, so omitting the manager from `set()` inside the migration would attempt a nested `crud-config-set` owner and fail.

With `useTransaction: false`, execution does not open the migration-wide owner and callbacks receive `undefined`. A `set()` call without a manager still owns its own atomic `crud-config-set` transaction. Multiple config writes therefore do not commit or roll back as one unit in disabled mode.

## Migration status enum

The migration system uses `EConfigMigrationStatus`:

```typescript copy
import { EConfigMigrationStatus } from "@elsikora/nestjs-crud-config";

EConfigMigrationStatus.PENDING;
EConfigMigrationStatus.RUNNING;
EConfigMigrationStatus.COMPLETED;
EConfigMigrationStatus.FAILED;
EConfigMigrationStatus.STUCK;
```

## Advanced configuration (async registration)

Custom migration table name must be provided statically (module compilation time) via `staticOptions.migrationEntityOptions`:

```typescript copy
CrudConfigModule.registerAsync({
 imports: [ConfigModule],
 inject: [ConfigService],
 useFactory: async (configService: ConfigService) => ({
  environment: configService.get("NODE_ENV", "development"),
  migrationOptions: {
   isEnabled: true,
   shouldRunOnStartup: true,
   useTransaction: true,
   stuckMigrationTimeoutMinutes: 60,
   migrations: [/* your migrations */],
  },
 }),
 staticOptions: {
  migrationEntityOptions: {
   tableName: "my_migrations",
   maxNameLength: 256,
  },
 },
});
```
